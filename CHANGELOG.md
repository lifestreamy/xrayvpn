# Changelog

История изменений по выпущенным версиям. English version: [CHANGELOG.en.md](CHANGELOG.en.md).
Релизная политика — [docs/dev/RELEASE.md](docs/dev/RELEASE.md).

Формат:

- Новые версии сверху; на каждый релиз — секция `## vX.Y.Z — YYYY-MM-DD`.
- Категории внутри секции: **Added**, **Changed**, **Fixed**, **Removed**.
- Строка `Status:` — только у выпущенных версий, если статус не обычный.
- Записи собираются из коммитов и вносятся релизным коммитом; авто-bump версий нет.
- Пара RU/EN обновляется одним коммитом; структура секций зеркальна.

## v0.4.3 — 2026-10-13

Добавлен механизм обновления клиента; ломающих изменений нет.

### Added
- Команда `xrayvpn update`: проверка и установка обновлений из Releases. Standalone-сборка обновляется
  на месте — скачивание, сверка sha256, прежний файл остаётся рядом как `.old`, затем предложение
  перезапуска; закрепления и ярлыки продолжают работать. Флаги: `--check` — только проверка (код
  выхода 10, если обновление есть), `--yes` — без подтверждений, `--dry-run` — план без скачивания,
  `--version X` — конкретная версия.
- `xrayvpn update list` — последние стабильные версии (`--limit`, `--pre`); справка во всех точках входа.

### Changed
- Строка «доступно обновление» предлагает запустить `xrayvpn update`; `--skip`/`--unskip` скрывают
  уведомление до следующей версии.
- В менеджерных установках (uv tool, pipx, pip, Homebrew, apt, winget, AUR) `update` файлы не
  подменяет: выводит команду канала; `uv tool`/`pipx` выполняет после подтверждения.
- `update list` показывает только версии с готовыми сборками; пин на сборку старше 0.4.3
  предупреждает, что команды `update` там нет.

## v0.4.2 — 2026-10-11

### Added
- Рядом с версией показывается дата релиза: баннер, `--version` и команда `version` в сессии.

### Fixed
- Windows: любое удалённое действие (`deploy`, `service`) падало с `'charmap' codec can't
  decode byte 0x9d`: fabric сам читал `~/.ssh/config` в системной кодировке и падал на
  не-ASCII содержимом. Fabric больше не читает ssh config — алиасы разрешает клиент и
  передаёт host/user/port/key явно.
- Windows: тот же класс — вывод WSL и ssh config декодируются явно (utf-8); локализованный
  вывод `wsl --status` больше не ломает определение WSL.
- Deploy: алиас `~/.ssh/config` в `ansible_host` личного `inventory.yml` снова резолвится
  для remote-деплоя (паритет с `service`).
- REALITY: пустой short ID больше не перенимается из старого конфига и не сохраняется в
  state; на сервере пустой short ID остаётся разрешённым — уже выданные профили работают.

## v0.4.1 — 2026-09-22

Релиз v0.4.0 не выпускался: секция описывает 0.4.x-линию целиком.

### Added
- Консольная сессия (REPL): запуск `xrayvpn` без аргументов — тот же интерактивный мастер, но
  с сессией: `deploy`/`help`/`version`/`lang ru|en`/`exit`, синтаксис команд как у CLI; режим
  selftest для проверок в CI.
- Standalone-сборки в Releases (Windows x64, Linux x64/arm64, macOS arm64): Nuitka onefile,
  встроенный payload (роли/плейбуки/конфиг-шаблон), распаковка в стабильный кэш-каталог — клиент
  работает без Python, uv и клона репозитория; версия проставлена в свойства exe.
- Колесо Python возит payload внутри (`xrayvpn/payload/…`): установка в чистое окружение даёт
  рабочий `deploy --dry-run` вне репозитория. Публикация на PyPI — `pip install xrayvpn`.
- Пакет `.deb` в ассетах релиза и apt-репозиторий (`apt install xrayvpn`, Ubuntu/Debian):
  подписанные метаданные, публичный ключ на постоянном URL; в пакете — ярлык `.desktop`
  с `Terminal=true` и иконкой (запуск двойным кликом).
- Проверка новых релизов в бинарных сборках: подсказка под баннером и после `--version`
  (кэш 24 часа; при сбое запроса ничего не выводится); отключение — `XRAYVPN_UPDATE_CHECK=0`.
- Команда `xrayvpn service` (`status`/`restart`/`logs`/`reboot`): обслуживание сервера поверх SSH
  по белому списку команд; `status` показывает подробный срез состояния сервиса и версий.
- Опция `deploy --no-config-download`: клиентские конфиги остаются на сервере.
- Роль: логи Xray только в journald, журнал сохраняется на диск; «чёрный ящик» xray-obs (снимки
  состояния каждые 10 минут) и watchdog выхода в сеть с детекцией журнального шторма — процедуры
  в RUNBOOK.
- Сборка и дистрибуция: матрица четырёх платформ со smoke-проверками из нейтрального каталога,
  версионированные имена ассетов, `SHA256SUMS.txt` и `latest.json` (манифест для будущей команды
  самообновления).
- Анти-петля: в сгенерированных Clash/Mihomo-профилях IP сервера закреплён правилом DIRECT —
  туннель не перехватывает собственное соединение клиента с VPS.
- Фатальная ошибка двойного клика по packaged-сборке остаётся на экране до Enter.
- Иконки: растровый мастер 3072×3072 и генератор производных (ICO для Windows, preview) с
  проверкой побайтового совпадения в тестах.
- Руководство RUNBOOK (аварийное восстановление) и разделение документации на пользовательскую
  и разработческую.

### Changed
- **Breaking**: `xrayvpn deploy` по умолчанию выполняет `--execution remote` (было `local`): запуск
  без аргументов разворачивает удалённый VPS (спрашивает IP и пароль); локальный режим — через
  явный `--execution local`.
- `--ru` (глобальный и у `deploy`) и переменная окружения `XRAYVPN_LANG`: полностью русскоязычный
  интерфейс CLI — промпты, сообщения, ошибки и `--help`; флаг работает в любой позиции аргументов.
  Лаунчеры двойного клика (`xrayvpn-deploy.pyw` / `xrayvpn-deploy-ru.pyw`) запускают интерпретатор
  напрямую, без обёртки `pwsh -c`.
- Цветной интерфейс: семантические цветовые токены, палитра truecolor, баннер v2.2, оформленные
  панели `--help`; VT включается самостоятельно, в том числе в классическом окне conhost.
- Хост можно задавать именем из `~/.ssh/config` — в `deploy` (включая локальный режим) и `service`.
- Remote-деплой: прогресс bootstrap с heartbeat; guard малой памяти — при RAM < 1024 МБ и
  отсутствии активного swap клиент предлагает создать swap-файл 1 ГБ (явный opt-in; существующие
  настройки swap/fstab не трогаются).
- Установка команды в PATH: `uv tool install` — голый `xrayvpn` без префикса `uv run`.
- Флаги ротации и ключевые параметры проброшены в shell-обёртки: `--rotate`/`--no-rotate`,
  `--runtime`, `-Warp/-NoWarp`, `-Rotate/-NoRotate`, порты и число клиентов.
- `deploy --help` показывает фактические значения по умолчанию из `config/settings.yml` и примеры;
  ответ о смене языка — одной строкой; остановка команды (Ctrl-C) не закрывает сессию.
- `ufw` больше не устанавливается ролью: allow-правило для `xray_port`/tcp добавляется, только
  если `ufw` уже есть на сервере. Переменная и флаг переименованы в `xray_manage_ufw` /
  `--manage-ufw/--no-ufw`.
- По завершении деплоя — баннер с итогом и подсказкой импорта конфигов; после прерванного деплоя
  клиент предлагает просто повторить запуск (шаги идемпотентны); одновременные деплои
  сериализуются блокировкой.
- Тесты клиента в CI — дополнительно на Windows и macOS; uv с фиксированной версией; smoke-проверки
  shell-обёрток отдельными job'ами.
- Контактные ссылки автора переведены на домен korelov.dev; репозиторий переименован в
  `lifestreamy/xrayvpn` (старый адрес перенаправляется).

### Fixed
- Двойной клик по `xrayvpn-deploy.pyw` на Windows падал (экранирование кавычек внутри лаунчера):
  прямой запуск интерпретатора, корректный код возврата, диагностика при отсутствии `.venv`/`uv`.
- `set -e` больше не обрывает dry-run и интерактивные вопросы в shell-обёртках; dry-run работает
  без inventory и не трогает личный `inventory.yml`.
- Понятные сообщения при сбоях SSH; пустой пароль и несуществующий файл ключа отклоняются сразу,
  с подсказкой.
- Двойной клик по packaged-exe под conhost перезапускает клиент в окне conhost с иконкой
  приложения (остаться в Windows Terminal — `--wt`/`XRAYVPN_IN_WT`).
- Локальный деплой уважает запись `~/.ssh/config` (порт и пользователь) вместо жёсткого `root:22`.
- Логи и статус сервиса: служебные строки не засоряют вывод, `logs` прерывается по Ctrl-C.
- Роль: пути бэкапов берут дату из `ansible_facts` (`date_time`), а не из окружения Ansible;
  vless-inbound тегирован — проверка в molecule не падает на отсутствующем атрибуте.
- В `--help` значения логических флагов по умолчанию выводятся словами
  (`default: enabled` / `default: disabled`).
- Баннер подстраивается под ширину терминала: длинные строки переносятся, узкое окно (<72 колонок)
  рисует экран без рамок, внешняя рамка одинаковая для RU и EN.

### Removed
- Рантайм `podman` (экспериментальный стаб, никогда не покидал experimental; не покрыт
  molecule-тестами). Поддерживаемые рантаймы: `native` (по умолчанию) и `docker`.

## v0.3 — 2026-09-05

Status: experimental.

### Added
- Основной CLI-клиент `xrayvpn` (Python): удалённый режим по SSH и локальный режим, все частые
  параметры — флагами.
- CI на GitHub Actions: workflow `molecule` — syntax-проверка, molecule-матрица ubuntu 22.04/24.04
  и debian 12, полный хост-прогон с файрволом и e2e через mihomo-клиент; workflow `python-client` —
  тесты и линт CLI.
- Руководство ручной локальной проверки — `docs/dev/TEST-LOCAL.md` (+EN).
- Релизная политика — `docs/dev/RELEASE.md` (+EN): статусы experimental/stable, схема тегов,
  порядок выпуска. CHANGELOG-пара (этот файл и `CHANGELOG.en.md`).
- Подсказки клиентам, когда `inventory.yml` отсутствует или не заполнен.
- Опция включения `xray.service` при загрузке и авто-установка `ufw`/`python3-venv` при развёртывании.

### Changed
- Все параметры роли собраны в одном `config/settings.yml`; `group_vars/` и роль-дефолты удалены.
- Выбор рантайма: `native` (по умолчанию), `docker`, `podman` (экспериментально).
- Docker- и podman-юниты работают в `--network host` — без лишнего NAT-хопа.
- Структура: `shell-clients/`, `python-client/`, `scripts/`, `config/`; инструменты разработки
  отделены от клиентских обёрток.
- Быстрый старт README: три пути запуска (клиенты и «голый» Ansible) с прямыми ссылками на файлы,
  подробности — в сворачиваемых блоках.

### Fixed
- Понятные сообщения об ошибках при проблемах с inventory; починен разбор `--use-inventory`
  в shell-клиентах.

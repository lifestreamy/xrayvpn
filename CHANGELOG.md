# Changelog

История изменений по версиям. English version: [CHANGELOG.en.md](CHANGELOG.en.md).
Политика выпусков и статусы релизов — [docs/dev/RELEASE.md](docs/dev/RELEASE.md).

Формат:

- Новые версии сверху; на каждый релиз — секция `## vX.Y.Z — YYYY-MM-DD`.
- Внутри секции — категории: **Added** (добавлено), **Changed** (изменено), **Fixed** (исправлено), **Removed** (удалено).
- В секции релиза — строка `Status:` (`experimental`, при переводе — `stable с YYYY-MM-DD`).
- Записи формируются из сообщений коммитов и вносятся релизным коммитом; авто-bump версий нет.
- Пара RU/EN обновляется одним коммитом; структура секций зеркальна.

## v0.4.1 — 2026-09-12

Status: готовится (разработка завершена на `staging`; публикация — вручную по завершении 0.4.x-линии).
Секция склеивает неотпущенный v0.4.0 и наработки после него; релиз v0.4.0 не выпускался.

### Added
- Консольная сессия (REPL): запуск `xrayvpn` без аргументов — тот же интерактивный мастер, но
  с сессией: `deploy`/`help`/`version`/`lang ru|en`/`exit`, синтаксис команд как у CLI; режим
  selftest для CI-дымов.
- Standalone-сборки в Releases (Windows x64, Linux x64/arm64, macOS arm64): Nuitka onefile,
  встроенный payload (роли/плейбуки/конфиг-шаблон), распаковка в стабильный кэш-каталог — клиент
  работает без Python, uv и клона репозитория. Метаданные версии Windows-файла (свойства exe).
- Колесо Python теперь возит payload внутри (`xrayvpn/payload/…`) и при установке из чистого
  окружения даёт рабочий `deploy --dry-run` вне репозитория.
- Проверка наличия новых релизов в бинарных сборках (не чаще раза в сутки, молча при сбоях,
  молча до первого stable-релиза); отключение — `XRAYVPN_UPDATE_CHECK=0`.
- Workflow сборки standalone-приложения и дистрибуции: матрица четырёх платформ с дымовыми проверками из
  нейтрального каталога, артефакты релиза, `SHA256SUMS.txt` и `latest.json`
  (манифест для будущей команды самообновления), draft-релиз по тегу.
- Анти-hairpin: в сгенерированных Clash/Mihomo-профилях IP сервера закреплён правилом DIRECT —
  туннель не перехватывает собственное соединение клиента с VPS.
- Краш-сеть packaged-сборки: фатальная ошибка двойного клика остаётся на экране до Enter.

### Changed
- **Breaking**: `xrayvpn deploy` по умолчанию выполняет `--execution remote` (было `local`): запуск
  без аргументов разворачивает удалённый VPS (спрашивает IP и пароль); локальный режим — через
  явный `--execution local`.
- Remote-деплой: guard малой памяти — при RAM < 1024 МБ и отсутствии активного swap клиент
  предлагает создать swap-файл `/swapfile` 1 ГБ (явный opt-in-вопрос; существующие настройки
  swap/fstab не трогаются).
- `ufw` больше не устанавливается ролью: allow-правило для `xray_port`/tcp добавляется только если
  `ufw` уже есть на сервере. Переменная `xray_manage_firewall` и CLI-флаг переименованы в
  `xray_manage_ufw` / `--manage-ufw/--no-ufw`.
- `--ru` (глобальный и у `deploy`) и переменная окружения `XRAYVPN_LANG`: полностью русскоязычный
  интерфейс CLI — промпты, сообщения, ошибки и `--help`; флаг работает в любой позиции аргументов.
  Лаунчеры двойного клика на Windows — английский и русский (`xrayvpn-deploy.pyw` /
  `xrayvpn-deploy-ru.pyw`), держат консоль открытой до Enter; запуск без обёртки `pwsh -c`,
  код возврата не глотается.
- Установка команды в PATH: `uv tool install --editable python-client` — голый `xrayvpn` без
  префикса `uv run`; дистрибутив переименован в `xrayvpn` (установка/удаление по этому имени).
- Флаги ротации и ключевые параметры проброшены в shell-обёртки: `--rotate`/`--no-rotate`,
  `--runtime`, `-Warp/-NoWarp`, `-Rotate/-NoRotate`, порты и число клиентов.
- В `deploy --help` показаны фактические значения по умолчанию из `config/settings.yml` и примеры;
  ответ о смене языка — одной строкой на новом языке; остановка команды (Ctrl-C) не закрывает сессию.
- Контактные ссылки автора переведены на домен korelov.dev (путь GitHub-репозитория не меняется).
- Тесты клиента в CI — дополнительно на Windows и macOS; uv с фиксированной версией.

### Fixed
- Двойной клик по `xrayvpn-deploy.pyw` на Windows падал (cmd-экранирование кавычек в лаунчере):
  прямой запуск интерпретатора без cmd, честный код возврата, явная диагностика при отсутствии
  `.venv`/`uv`; контракт лаунчеров в тестах проверяется реальным запуском, а не только статически.
- `set -e` больше не обрывает dry-run и интерактивные допросы в shell-обёртках; dry-run-превью
  работает без всякого inventory и не трогает личный `inventory.yml`.

### Removed
- Рантайм `podman` (экспериментальный стаб, никогда не покидал experimental; не покрыт
  molecule-тестами). Поддерживаемые рантаймы: `native` (по умолчанию) и `docker`.

## v0.3 — 2026-09-05

Status: experimental (критерии перевода в stable — `docs/dev/RELEASE.md`).

### Added
- Основной CLI-клиент `xrayvpn` (Python): удалённый режим по SSH и локальный режим, все частые
  параметры — флагами.
- CI на GitHub Actions: workflow `molecule` — syntax-проверка, molecule-матрица ubuntu 22.04/24.04
  и debian 12, полный хост-прогон с файрволом и e2e через mihomo-клиент; workflow `python-client` —
  тесты и линт CLI.
- Руководство ручной локальной проверки — `docs/dev/TEST-LOCAL.md` (+EN).
- Релизная политика — `docs/dev/RELEASE.md` (+EN): статусы experimental/stable, схема тегов,
  порядок выпуска. CHANGELOG-пара (этот файл и `CHANGELOG.en.md`).
- Подсказки клиентам, когда `inventory.yml` отсутствует или не заполнен.
- Опция включения `xray.service` при загрузке и авто-установка `ufw`/`python3-venv` при развёртывании.

### Changed
- Все параметры роли собраны в одном `config/settings.yml`; `group_vars/` и роль-дефолты удалены.
- Выбор рантайма: `native` (по умолчанию), `docker`, `podman` (экспериментально).
- Docker- и podman-юниты работают в `--network host` — без лишнего NAT-хопа.
- Структура: `shell-clients/`, `python-client/`, `scripts/`, `config/`; инструменты разработки
  отделены от клиентских обёрток.
- Быстрый старт README: три пути запуска (клиенты и «голый» Ansible) с прямыми ссылками на файлы,
  подробности — в сворачиваемых блоках.

### Fixed
- Понятные сообщения об ошибках при проблемах с inventory; чинен разбор `--use-inventory`
  в shell-клиентах.

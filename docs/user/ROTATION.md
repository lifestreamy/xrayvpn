# Ротация — Runbook

Я написал этот runbook как памятку, после того, как самому пришлось ротировать ключи на своём VPS. Если что-то не совпадает с реальной работой — откройте issue, поправлю. Руководство применимо, когда на вашем VPS уже было развёртывание этой утилитой. Если развёртывание было выполнено другой утилитой — работоспособность не гарантируется, и рекомендуется предварительно удалить старые развёртывания.

## Что такое ротация и в каких случаях её делать

**Ротация** — это замена учётных данных VPN на новые: ключей, идентификаторов клиентов и связанных файлов. После ротации старые конфиги клиентов перестают подключаться, нужно раздать новые.

Когда её делают:

- **Компрометация.** Вы узнали (или подозреваете), что ключи или short ID REALITY утекли. В этом случае ротация — обязательное действие. Не откладывайте.
- **Личный график.** Вы сами решили, что ключи стоит менять регулярно — например, раз в 90 дней, на всякий случай.
- **Тест.** Хотите заранее убедиться, что ротация вообще работает на вашем VPS — что резервные копии пишутся, новые конфиги скачиваются, клиенты переподключаются. Тогда прогоняете процедуру один раз «вхолостую», а после неё возвращаете ключи на исходные (см. §5 ниже).

Во всех случаях алгоритм одинаковый — раздел §2 ниже.

## Глоссарий

Коротко — термины, которые встречаются в этом файле. Все термины проекта — в [`docs/user/GLOSSARY.md`](GLOSSARY.md).

- **Ротация** — замена учётных данных на новые. Старые данные перестают работать.
- **Переключатель `xray_reality_rotate`** — параметр, который заставляет роль пересоздать ключи, short ID и UUID клиентов.
- **REALITY** — технология стелс-VPN в Xray, маскирующая сервер под чужой легитимный сайт.
- **WARP** — дополнительный исходящий туннель через Cloudflare. Ротируется отдельной процедурой (см. §4).
- **`<VPS_IP>`** — IP-адрес вашего VPS. Заменяйте перед запуском команд.

## 1. Как управлять настройкой ротации

Три сценария:

| Составляющая | Где живёт / действие | Эффект |
|---|---|---|
| Изменение `xray_reality_rotate` | `config/settings.yml` или `-e ...` | Полная смена REALITY-ключей, short ID и UUID клиентов. |
| Изменение `num_clients` | `config/settings.yml` | Сколько клиентских конфигов сгенерировать. Без `xray_reality_rotate: true` действует как добавление/уменьшение. |
| Ротация WARP | `/root/xray-config/wgcf-account.toml`, `/root/xray-config/wgcf-profile.conf` — удалить вручную, затем rerun | Смена учётных данных WARP (если он включён). Не зависит от `xray_reality_rotate`. Подробности в §4. |

## 2. Ротация идентичности REALITY

### Как включить полную ротацию

У роли один переключатель:

```yaml
xray_reality_rotate: true
```

Передайте его через `config/settings.yml` для разового запуска, либо через `-e xray_reality_rotate=true` в командной строке:

```bash
ansible-playbook -i inventory.yml deploy.yml -e xray_reality_rotate=true
```

### Что меняется

| Что меняется | Без ротации (по умолчанию) | С ротацией (`xray_reality_rotate: true`) |
|---|---|---|
| REALITY `private_key` | ❌ не трогается | ✅ генерируется заново |
| REALITY `public_key` | ❌ не трогается | ✅ генерируется заново |
| REALITY `short_id` | ❌ не трогается | ✅ генерируется заново |
| Client UUIDs (в `reality-state.json`) | ❌ сохраняются; новые UUID добавляются только при увеличении `num_clients` | ✅ все пересоздаются |
| `/root/xray-config/reality-state.json` | ❌ перезаписывается только если нужно дополнить UUID до `num_clients` | ✅ перезаписывается |
| `/root/xray-config/reality-state.json.bak-YYYY-MM-DD-HH:MM:SS` | ❌ не создаётся | ✅ создаётся из старого состояния |
| `/etc/xray/config.json` | ❌ пересобирается из сохранённого state и параметров (без изменений ключей) | ✅ пересобирается с новыми ключами |
| `/root/vpn-configs/*.json` и `*.yaml` (на VPS) | ❌ перезаписываются на основе того же state | ✅ перезаписываются с новыми UUID |
| `downloaded-clients/` (локально) | ❌ совпадает с предыдущим прогоном | ✅ новые конфиги с новыми UUID |
| WARP credentials (`wgcf-account.toml`, `wgcf-profile.conf`) | ⚠️ ротируются отдельно, см. §4 ниже | ⚠️ ротируются отдельно, см. §4 ниже |

⚠️ — меняется отдельной процедурой, не `xray_reality_rotate`.

### Увеличить или уменьшить число клиентов

Если вы изменили `num_clients` и запустили playbook без `xray_reality_rotate: true`:

- Увеличили `num_clients` → в `reality-state.json` добавляются новые UUID, экспортируются новые клиентские конфиги.
- Уменьшили `num_clients` → существующие UUID сохраняются, экспортируется меньше конфигов.
- Увеличили обратно → ранее сохранённые UUID снова используются.

Если переключатель в состоянии `xray_reality_rotate: true`, все клиентские секреты будут обновлены.

### Что происходит при ротации

Подробное сравнение — в таблице выше. Кратко:

1. Текущий `reality-state.json` копируется в резервную копию `reality-state.json.bak-YYYY-MM-DD-HH:MM:SS` в той же папке.
2. Файл текущего состояния удаляется.
3. Генерируется новая X25519-пара ключей, новый случайный short ID, новые клиентские UUID.
4. Записывается новый `reality-state.json`.
5. Сервис Xray перезапускается с обновлённым `config.json`.

Сразу после прогона проверьте, что появились резервная копия старого состояния и новый `reality-state.json`:

```bash
ls -la /root/xray-config/reality-state.json*   # должны быть видны резервная копия и новый файл
```

### После прогона

- Новые клиентские конфиги загрузятся локально в папку проекта, откуда производился запуск `/downloaded-clients/`, а также сохранятся в `/root/vpn-configs/` на VPS.
- Загрузите новые конфиги в ваши vpn-клиенты: Clash Verge / FlClash / Amnezia.
- Верните `xray_reality_rotate` в `false` в `config/settings.yml`, если хотите сохранять идентичность при следующих запусках.

## 4. Ротация учётных данных WARP

Учётные данные WARP получаются через `wgcf` и хранятся в двух файлах на VPS:

- `/root/xray-config/wgcf-account.toml`
- `/root/xray-config/wgcf-profile.conf`

Важно: `wgcf-identity.json` в этой конфигурации не используется. В старых версиях runbook этот файл упоминался — игнорируйте те упоминания.

Чтобы выполнить ротацию:

1. Зайдите на VPS по SSH:

   ```bash
   ssh root@<VPS_IP>   # <VPS_IP> замените на свой IP
   ```

2. Удалите оба файла выше:

   ```bash
   rm -v /root/xray-config/wgcf-account.toml /root/xray-config/wgcf-profile.conf   # удаляем оба файла
   ```

3. Перезапустите playbook. Роль вызовет `wgcf register` и `wgcf generate` заново, и WARP outbound в `xray_config.json` подхватит новые учётные данные. Если работаете через локальную машину (не сразу на VPS), команда та же:

   ```bash
   ansible-playbook -i inventory.yml deploy.yml   # другие способы запуска см. в README.md
   ```

Проверяйте WARP-маршрутизацию снаружи VPS, через VPN-клиент. Не полагайтесь на `curl` из контейнера Xray.

С машины, на которой работает VPN-клиент (ноутбук, телефон, другой сервер), проверьте внешний IP. При успешном развёртывании он покажет IP VPS или IP Cloudflare, если WARP включён:

```bash
curl -4 https://ifconfig.io   # выполнить на устройстве клиента, не на VPS
curl -4 https://cloudflare.com/cdn-cgi/trace   # альтернатива, в выводе ищите colo= и ip=
```

## 5. Восстановление

Роль создаёт резервную копию с меткой времени перед ротацией. Типичное восстановление:

1. Зайдите на VPS по SSH: `ssh root@<VPS_IP>`.
2. Посмотрите резервные копии: `ls -la /root/xray-config/reality-state.json.bak-*`.
3. Если хотите откатиться на предыдущее состояние. Подставьте вместо `YYYY-MM-DD-HH:MM:SS` реальное имя резервной копии из шага 2:
   ```bash
   cp /root/xray-config/reality-state.json.bak-YYYY-MM-DD-HH:MM:SS \
      /root/xray-config/reality-state.json
   chown root:root /root/xray-config/reality-state.json
   chmod 0600 /root/xray-config/reality-state.json
   ```
4. Убедитесь, что в `config/settings.yml` стоит `xray_reality_rotate: false`.
5. Перезапустите playbook. Роль подхватит восстановленное состояние и перегенерирует `config.json` и клиентские конфиги под него.

Держите последнюю резервную копию, пока не проверите новую ротацию целиком.
